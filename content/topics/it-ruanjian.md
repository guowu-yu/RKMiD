## 一、概念与定位

软件工程是用工程化方法**经济、可靠地开发高质量软件**的学科。在系统集成项目管理中，软件工程既是技术基础（理解承建方"怎么干活"），也是范围与质量管理的前置知识。本章重点掌握"生命周期模型怎么选""需求怎么管""架构怎么分"以及"UML 图怎么读"，上午题约占 5–8 分，并常嵌入案例的技术背景。

## 二、核心知识

### 1. 软件生命周期模型
| 模型 | 特点 | 适用 |
|---|---|---|
| 瀑布模型 | 阶段顺序、文档驱动 | 需求明确稳定 |
| 原型模型 | 先造原型确认需求 | 需求模糊 |
| 螺旋模型 | 瀑布+演进+风险分析 | 大型、高风险 |
| 迭代/增量 | 分版本完善 | 中大型系统 |
| V 模型 | 强调测试与阶段对应 | 对质量验证要求高 |
| 喷泉模型 | 面向对象、各阶段重叠 | OO 开发 |

### 2. 需求工程（RE）
需求工程是把"用户需要什么"转为"规格说明"的过程，含：
- **需求获取**：访谈、问卷、原型、观察、联合需求计划（JRP）。
- **需求分析**：建模、优先级划分、冲突消解。
- **需求规格**：编写 SRS（软件需求规格说明书）。
- **需求验证**：评审、原型确认，确保"正确、完整、一致、可测"。
- **需求管理**：跟踪、变更控制（与配置/变更管理衔接）。

需求分**业务需求、用户需求、系统需求（功能/非功能）**、质量属性（性能、安全、可用性等）。

### 3. 系统架构风格
| 风格 | 描述 | 例子 |
|---|---|---|
| 数据流（管道-过滤器） | 数据经处理单元流动 | 编译器 |
| 调用/返回 | 主程序-子程序、OO | 传统分层系统 |
| 独立构件 | 事件驱动、C/S | GUI、消息系统 |
| 虚拟机 | 解释器、规则引擎 | 工作流引擎 |
| 仓库（数据共享） | 中央数据存储 | 数据库、黑板系统 |

分层架构（表现层/业务层/数据层）是信息系统最常用风格。

### 4. UML 常用图
- **用例图**：功能与参与者关系（需求视角）。
- **类图**：静态结构、类与关联（设计视角）。
- **时序图**：对象间消息按时间顺序（交互）。
- **活动图**：业务流程/工作流（类似流程图）。
此外还有状态图、组件图、部署图等，共 13 种图（结构图 7+行为图 6）。

### 5. 软件质量模型（McCall / ISO/IEC 25010）
常见质量属性：功能性、可靠性、易用性、效率、可维护性、可移植性。强调"质量需可度量、可测试"。

## 三、方法流程

典型瀑布式开发流程：可行性 → 需求 → 设计（概要/详细）→ 编码 → 测试 → 运维。需求阶段产出 SRS，设计阶段产出设计说明书，二者是后续配置项与基线的基础。

需求变更流程：提出 → 影响分析 → CCB 审批 → 实施与验证 → 配置更新。这与整体变更控制一致。

## 四、易错点

- **需求 vs 设计**：需求描述"做什么"（用户视角、可验证），设计描述"怎么做"（技术视角）。考题常混淆"SRS 属于需求还是设计"——SRS 属需求阶段产物。
- **原型模型目的**是确认需求，不是最终产品（除非演进式原型）。
- **螺旋模型核心是风险分析**，区别于普通迭代。
- **UML 用例图不画内部流程**，活动/时序图才表达流程；类图表达静态结构而非行为。
- 架构风格是"总体组织方式"，不等于具体技术选型。
